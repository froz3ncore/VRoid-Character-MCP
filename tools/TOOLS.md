## Session and status

### `restart_session`

- annotations: destructive
- parameters:
  - `discard_unsaved` — boolean (optional, default false)

Recreate only this MCP-owned VRoid copy, discarding its unsaved changes.

Requires explicit discard_unsaved=true. Save first when you can; this is not
a way to silently drop a user's work. The new model token invalidates every
id issued before it. It also recovers from COPY_DISCONNECTED or an uncertain
native call, and other VRoid processes are never touched.

### `get_status`

- annotations: read-only
- parameters: none

Report the copy, current model, background work and model update state.

The response also carries tool_count and toolset_hash, so a client that
cached an older tool list can tell whether it needs to reload instead of
guessing.

### `attach_open_vroid`

- annotations: destructive
- parameters:
  - `pid` — integer | null (optional, default null)
  - `discard_copy_unsaved` — boolean (optional, default false)

Attach to a user-opened VRoid process without closing it on detach.

Edits act on that real session, including its unsaved model. If the MCP
copy is running, explicitly set discard_copy_unsaved after saving it.
Multiple candidate processes require a PID. Other MCP labs are excluded.
Attached mode does not load the lab isolation guard. Save character files
in VRoid itself; custom item saves use the target window's profile.

### `detach_open_vroid`

- annotations: edit
- parameters: none

Detach from the user-opened VRoid without closing its process or saving it.

## Parameters, presets and saving

### `list_parameters`

- annotations: read-only
- parameters:
  - `domain` — string (**required**)
  - `scope` — string | null (optional, default null)
  - `category` — string | null (optional, default null)
  - `offset` — integer (optional, default 0)
  - `limit` — integer (optional, default 200)

List typed native controls with their values, units, ranges and options.

Hair needs a category and a node scope, accessories an instance scope, and
expressions may take an expression id as scope. Colors are RGBA in 0..1.
Read every next_offset page before concluding a control is missing. The
general domain covers outline, rim light, shading, gaze limits and spring
amplitude. Shape controls add semantic_key/group/bindings and a
translation_key; `name` is an exact-key English correction while `label`
stays native. Missing bindings are reported instead of guessed, and a
semantic key may repeat across controls and is never a write id. Colors add
native_value, mixed, color_bindings, shared_groups, alias_of and
affected_parameter_ids; a mixed aggregate such as BothEyes has a null value,
so use the separate side ids. Left and right follow the native UI controls,
which can be the opposite of the raw binding key names.

### `set_parameters`

- annotations: edit
- parameters:
  - `expected_model` — string (**required**)
  - `domain` — string (**required**)
  - `changes` — list[ParameterChange] (**required**)
  - `scope` — string | null (optional, default null)
  - `category` — string | null (optional, default null)

Write 1-64 typed parameters taken from a fresh list_parameters result.

Every value is validated before anything is written, and native history can
undo the batch. Value shapes: curve [x,y] control points, quaternion
[x,y,z,w], vector [x,y,z], color [r,g,b,a]. Hair needs category and node
scope, accessories an instance scope. A native error can leave a partial
batch, so inspect ok/applied/error. Changing a preset or the hair structure
means relisting. Color batches reject overlapping targets (BothEyes together
with one eye, or a duplicated shared alias) while separate eyes may be set in
one call; writing BothEyes unifies them. Color results include settled
affected_parameters and a per-write verification from each binding.

## Capture and review

### `screenshot`

- annotations: read-only
- parameters:
  - `expected_model` — string (**required**)
  - `view` — string (optional, default `front`)
  - `size` — integer (optional, default 512)
  - `quality` — string (optional, default `balanced`)

Return one native PNG; use the photo view for a posed preview.

Legacy views are front/side/back/three_quarter plus the full_ variants.
Regional views are REGION_ANGLE with REGION in
body/face/head/upper/legs/feet and ANGLE in
front/back/left/right/three_quarter_left/three_quarter_right (for example
face_left); left and right are observer sides seen from the front, and
regional views need edit mode. Quality: legacy is a single sample, balanced
adds 4x MSAA, high adds 4x MSAA with a 2x render scale. Internal rendering is
capped at 8M pixels while the output stays within 256..2048, and the GPU may
reduce MSAA. Use capture_review when the effective quality metadata matters.
Photo camera settings are restored after the capture.

### `capture_review`

- annotations: edit
- parameters:
  - `expected_model` — string (**required**)
  - `label` — string (optional, default ``)
  - `views` — list[string] | null (optional, default null)
  - `size` — integer (optional, default 1024)
  - `baseline_id` — string | null (optional, default null)
  - `quality` — string (optional, default `balanced`)

Capture 1-6 native views for visual inspection and save the PNGs plus numeric state.

Defaults to front, three_quarter, full_front and full_back, and requires edit
mode. REGION_ANGLE views work as documented for screenshot; one regional batch
shares its measured bounds, and a baseline from the same model locks those
bounds while another model gets fresh ones. The response carries the images,
their paths, the model height, the capture id and a visual checklist. There is
no OCR, no click automation, no beauty scoring and no automatic collision
verdict. Passing baseline_id from an earlier capture with the same views and
size yields before/after images and parameter differences for face, body,
clothing and colour; hair geometry changes still need visual inspection, and a
different model token is called out explicitly. The character is not edited or
saved: only review artifacts are written and the editor guides are hidden.

### `capture_wear_reference`
