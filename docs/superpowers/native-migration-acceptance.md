# Native acceptance for the mcjo79 migration

**Result: partial local acceptance.** See the [2026-11-13 PR review](../native-evidence/2026-11-13-pr1-acceptance.md) for the tested builds, cases, fixes and remaining gates. This checklist is for the changes listed in [MIGRATION.md](../../MIGRATION.md). Keep the offline test report separate. A static match in an allowlisted assembly establishes a signature or implementation detail on that build; it does not establish that an operation completes, survives Undo or produces the intended picture.

## Prepare a disposable run

1. Use an installation matching [the recognized builds](../../vroid_mcp/supported_builds.py), including any metadata pin. The pixiv-signed standalone 2.16.0 package is admitted; the Steam hash in the [historical audit](../native-evidence/2026-11-07-vroid-216.md) remains a static binding descriptor and is **not admitted**. Copy mode isolates settings and `vroid.closet` registry lookups per process: preserve the real protocol key and user profile. A separate Windows account and deletion of that key are not preparation requirements. For 2.14.0, ed65 is the signed standalone package and 793e has a historical assembly identity only. Recently added callbacks and item/hair descriptors can refuse on 793e.
2. In that test environment use `prepare_lab.py --source <installation> --lab <new-lab>` with the repository interpreter, then `tools/doctor.py --lab <new-lab>` before connecting. Keep the lab in the project, experimental files under project `temp/`, and use unique artifact names. Run one server against the lab. For attached checks, use a separate disposable window with explicit attachment and edit acknowledgements. See [recovery](../../RECOVERY.md) for the existing host requirements.
3. Record the Git revision, source revision, exact assembly/hash, mode, PID, timestamps, fixture hashes and initial model token. Discover current IDs from the tools; never reuse a token after reload, or substitute a display label for an ID. Retain each request, receipt, readback and relevant `Player.log` excerpt. Record a failure as `failed` or `uncertain`; stop dispatching if the session is uncertain. A later successful fresh run does not supersede the original evidence.
4. For each persistent edit capture the before state, the settled after state, Undo and Redo, then save to a new file, exit the disposable process and reopen the saved file in a fresh process. Reacquire IDs and compare values, assets and visible results. Record **command**, **readback**, **history**, **cold reopen**, **artifact** and **visual** results separately (`passed`, `failed`, `not run`, `not applicable`). Transient camera/preview operations should leave saved character data and history unchanged.

## Domain cases

| Case | Procedure and evidence required for a pass |
| --- | --- |
| Ordinary VRM export | Use a saved character with nondefault permissions and author data. Read `get_vrm_export_options`, then `export_vrm` to fresh VRM0 and VRM1 files. Compare omitted settings with a baseline and change one option at a time, including a choice discovered from this session. Record requested/effective values and any refusal. Exercise an already-open export screen and a tool-opened screen, both `leave` policies, two consecutive exports and subsequent editing. Confirm task completion, file stability, process survival after cleanup and no later crash in `Player.log`. Validate embedded references and metadata; count actual meshes, images, materials and bones for a reduction comparison. Import both artifacts in another consumer and inspect rendering/motion. A valid GLB alone does not pass that last check. |
| Groups, presets and files | Include active and stored groups of the same type, several garments, a mandatory part, a locked preset, a registered current-format custom item and a byte-identical project copy. Use exact discovered IDs and native ranges. Use `list_group_parameters` and `set_group_parameters` to exercise 0, one interior value and 100 on the exact worn garment, including a template path. Compare the settled readback, Undo/Redo and visible deformation. Confirm paired controls affect the intended side; unsupported raw scalar/enum writes and wrong owners do no work. Test material preservation with matching and missing bindings. Try both `apply_custom_item` and `apply_custom_item_by_key` in copy and acknowledged attached modes. Record whether the registered FileCustomItemModel is uniquely selectable before displaying its category and after displaying it. A registered file without an exact selectable option must be refused before selection. Reject stale/modified/unregistered files and verify inventory after removal. For an interrupted load retain its file pin until safe recovery; do not infer that every descendant vanished from one missing ID. |
| Body shape and measurement | Use F00 and M00 fixtures with translated model bounds. Compare native height/UI label, world-space top and `maxY - minY`; a translation must not change the extent. Include an unrelated renderer and a missing humanoid landmark. Check both height solvers within their declared bounds; do not interpret the optional BMI/waist heuristic as measured mass. Compare geometric readback, cold reopen and visible body/clothing shape separately. |
| Layer and material edits | Use asymmetric RGBA pixels, transparency, duplicate-looking layers at distinct addresses, two shared hair materials and custom layer metadata/order. Convert a real source material, reacquire layer IDs, replace one existing raster and compare decoded pixels, alpha, orientation and untouched metadata through Undo/Redo and cold reopen. Check multiply and luminance colorization, a zero-strength operation, stale hashes, dimension mismatch and multiple targets. Deduplicate shared targets; do not report unread native BaseColor as verified. Inspect edges over contrasting backgrounds. |
| Hair | Discover a real procedural node and a brush group with multiple strands, non-origin roots and nonidentity guides. Scale the group and compare each point relative to its own root; normals, UVs, materials and roots must persist. Clone and offset the whole group, verify new IDs and unchanged source geometry. Compare actual step receipts with changes and with Undo behavior. Test exact procedural Length and HairCount independently and together, including a hidden sibling and native range limits. The descriptor is build-specific; an unsupported descriptor must refuse without a write. Native control-point length, configured Length and visible strand length are different measurements. |
| Edit camera and face preview | Use two shape names with an ambiguous suffix and an unrelated renderer. `face_preview` must reject ambiguity without a setter. Apply one exact shape, verify at image pickup, reset to zero, restore, then let animation advance and repeat. Confirm fixed views remain independent of the current edit camera. Exercise camera modes, rotation, pan, zoom and projection; compare active primary camera pose and the rendered result after settling. Check that saved expression parameters and history remain unchanged. |
| Clean image and application frame | Use `screenshot_metadata` for portrait 640x1024 and landscape 1024x640 with a known circular marker or square. Record actual dimensions, projected proportions, framing, source raster, projection, effective MSAA/SSAA and file hash. Check fixed, current-editor and photo routes; exercise active hair/pose presentation, then induce a safe refusal or render failure and compare selections, overlays, targets and camera before/after. Call with `clean=false` and default render options to capture the real Unity application frame with visible UI; incompatible overrides must fail. Review orientation, guide visibility, deformation, alpha and edges from actual pixels. No desktop input is needed. |
| Catalog and framing | Sync all builtin pages and registered customs, including locked entries and revisions. Annotate an item, remove it, return it and repeat from a fresh server. Manual labels/history must survive; a partial custom scan must not mark missing registrations removed. Compare separately identified native-icon and situation-image bytes. Change and reset individual and all framing overrides; check saved versus effective values. Verify offline search, annotation and help from a cold server with zero native startup attempts. |
| Situation images | First reject attached mode and missing disposable-model acknowledgement before initialization/receipts. Use an owned copy with clothes, accessories, underwear and hair; verify the unique ZIP/CRC/hash restoration snapshot before stripping. An optional unremovable/unknown slot must refuse, while required face/body and BaseHair stay; never call this neutral anatomy. Record exact removed/retained slots and tested group/custom revisions. For a set, verify the exact native root/header/resource/type and bounded direct TransferableGroup entry graph; recommended/clear/ambiguous edges and extra active slots must refuse. Use translated bounds, nonfront yaw, numeric narrow/wide half-width regions, portrait/landscape aspects and full-body fit. Independently project all corners and check near/far planes, inactive regional inputs and requested/effective distance. Validate actual rendered pixels, orientation/proportions and hashes. Exercise >200 candidates, native-icon fallback, changed framing and refresh/limit. Confirm restoration from the same pinned snapshot hash with fresh identity; changed model/archive or uncertain work must stop without forcing restore. Preserve failed PNG/metadata in lab/temp and distinguish published rows from restore failure. Undo, dirty state and original file association need not survive. |
| Session, help and batch | Compare file association, dirty/readiness and history flags in copy and attached mode. Refuse dirty return/exit without explicit discard. Call `return_to_main_menu` and pass the returned `menu_token` as `expected_menu` to `create_from_menu` (F00/M00) or `open_from_menu`. Verify `confirm_attached` in attached mode, rejection of reused tokens, actual new variant/file association, unchanged PID and fresh `model_token`. Test empty Undo/Redo and a request for more steps than exist. Call `exit_vroid` (with explicit `close_attached` in attached mode) and verify graceful quit by actual process exit, no force-kill, and no implicit relaunch. Try a batch mixing reads, edits, an ordinary failure and images with a competing client; verify serialization, `requested`, `executed`, `failed`, `stopped_at`, `stop_reason`, per-operation `results`, and at most eight images / 16 MiB. Inspect partial work before continuing. On uncertain work, nested batch or disallowed lifecycle commands, confirm no unsafe next step. Check Chinese help/resource examples against live public schemas. |

In a disposable attached session, cancel a menu import and an ordinary VRM export after native dispatch. Check that review, acknowledgement and detach preserve the session, handles and source pin while the task is running. Repeat during custom loading and after selection but before its settled membership receipt. Once all owners report terminal state, inspect the actual model, file association and output before requesting a fresh review token. Verify acknowledgement releases the source pin without retrying the command or publishing an interrupted export.

For negative paths unsafe to induce in a real app (for example a lost reply during exit or a native allocator failure), retain the offline fault-injection receipt and mark the corresponding native case **not run**. Do not manufacture a native failure by killing an unrelated process or corrupting a user asset.

Task 8 review follow-up: the snapshot generation must already be read-sharing pinned and hash/CRC checked at the first clear, and remain pinned until verified restoration or explicit pending recovery. Attempt independent overwrite/delete at both clear and capture. Keep the original required-group identities frozen through every clear and row; test a set that replaces a required group followed by an unrelated category. Independently bind builtin ID/resource/type through `RestorationInfo.AssetStorage.AssetCatalog.GetTransferableGroupByName`; a PlayFab scan does not supply current revisions. Compare exact stored `Header.Custom.Revision` and `UpdatedSinceLastRevision` against active and leaf Info, refusing dirty/missing/incoherent versions. Cache reuse needs sufficient native version proof and actual nonuniform 512 image/quality/optical evidence, rather than a truthy revision or tiny icon. Race publication from a second process changing scan/build/ID/framing and separately annotating; only the independent annotation should survive successful publication. Read back the actual clone's canonical projection, position/orientation and finite near/far clips and project world corners/selected region through that matrix. Raster checks reject empty/transparent/uniform frames without asserting subject identity or beauty. Cancel after import dispatch and preserve incremental clear receipts, snapshot hash, pending import state and pin even then. A terminal import task plus a new token is insufficient: verify distinct engine, actual snapshot file association and original group inventory before reporting restored. All of these remain native/manual acceptance gates despite network-free double coverage.
