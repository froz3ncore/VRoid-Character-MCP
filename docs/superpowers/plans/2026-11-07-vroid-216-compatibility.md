# VRoid Studio 2.16.0 compatibility

This is part of the mcjo79 migration, scheduled before final integration. The target is the user's Windows workflow, including the installed Steam distribution and the official standalone download. The source tree remains a single Python MCP / Frida / JavaScript implementation. Retain both exact 2.14.0 descriptors and the established public schemas.

1. **Identify the builds.** Confirm the installed Steam app/depot and product version using native package evidence. Read the official Windows standalone release, verify its signer, and record installer, `GameAssembly.dll` and IL2CPP metadata digests. Compare the two distributions directly. A shared version number is not an interchangeable binary identity.
2. **Audit the native contract before admission.** Use metadata and relevant bodies to compare the bridge entry points, editor/file/history operations, ordinary VRM export, texture paths, camera and capture APIs, group inventory and custom registry refresh. Identify changed generated methods, overloads, delegate targets, fields and UI ownership. Re-derive the procedural hair writer and registry completion descriptors where they are version-specific. Distinguish static evidence from observations that require a running application.
3. **Implement version-aware dispatch.** Select an exact known build and its matching metadata in lab preparation, copy startup, attachment and diagnostics. Keep unrecognized and mismatched pairs fail-closed before dispatch. Share capabilities demonstrated common by the audit; select changed native names/roles by the verified build identity. Keep an unproven individual operation unavailable with an actionable error and an explicit row in the compatibility report, while preserving independently established operations. Never enable the whole 2.14.0 profile on a new hash by assumption. Report the actual observed application/build version; preserve earlier input/output contracts. This task does not imply adding features newly introduced by VRoid itself.
4. **Verify installation and behavior at the correct layer.** Exercise the actual package files with preparation/diagnostics, positive and negative build/metadata combinations, mapped 2.14.0/2.16.0 dispatch and real SDK stdio registration. Use native doubles for changed ABI paths and collect the exact static evidence. Obtain independent review and fix confirmed problems. Do not install over Steam, edit the user's registry or run/attach to the user's active model.
5. **Native and visual gates.** When there is a supported disposable physical copy and an eligible Windows test profile, run the normal crash guard, initialize, create/read an F00 model, edit a discovered parameter, read it back, Undo/Redo, save/reopen and ordinary VRM export. Test migrated native paths with targeted fixtures, including registry refresh, hair, cameras, gallery restoration, menu and graceful exit. Evaluate images separately. When a necessary native environment is unavailable, identify the exact unmet gate; mark only the static, host or offline evidence actually obtained. List both distributions and any remaining partial capability. The PR and workspace handoff must not imply that unrun gates passed.
